# M2.8 Mechanistic Synthetic Identifiability Protocol

**Status:** prospective pre-outcome protocol for mechanistic synthetic design

M2.8 is a known-truth synthetic milestone. It is not a real-data test of
Trident-G and it does not use Attention Coach wrapper-transfer outcomes.

No confirmatory Trident-G, APC, PACE, neural-criticality or cusp claim is
authorised by this protocol.

## Machine-Readable Design

The first pre-outcome M2.8 design scaffold is:

```text
config/mechanistic_identifiability_v1.yaml
```

It consumes the frozen M3 variable registry:

```text
config/hrp_stack_variable_registry_v2.yaml
4073c76357954a386b30d2cad792e4c6bb4eb393
```

The scaffold is schedule-only. It registers the known-truth family contrasts,
sample geometry and independent seed streams for a later generator smoke, but
does not authorise model fitting, pilot execution or real wrapper-transfer
outcome inspection.

## Relation To M2.7

M2.7 tested whether static M0/M1/M2_EM/M3/M4 architecture distinctions remain
usable after adding empirically realistic nuisance structure.

The exploratory M2.7 pilot established the following planning constraints:

```text
continuous/nonlinear structure remains useful;
M1 vs M2_EM specificity needs care;
static M3/M4 profile recovery is weak under realistic nuisance;
false discrete selection under ETW0-ETW2 was low in the pilot;
M2_EM convergence diagnostics should be monitored.
```

M2.8 does not optimise M2.7 to make every static world recover. It moves the
synthetic programme toward the variables that later Trident-G tests actually
need.

```text

distinguished from simpler alternatives under known truth?
```

The variables of interest are:


continuous APC and dynamic-regime variables.

## Scientific Boundary

M2.8 may compare candidate causal organisations, but it must not define a
preferred ontology into the generator or scoring rule.

Do not:

```text
force four profiles;
privilege M3/M4;
identify PACE with a latent ontology;
infer APC/PACE/Trident states from empirical-background estimates;
use transfer outcomes;
inspect real Attention Coach wrapper-transfer outcomes;
hard-code a cusp;
use empirical performance outcomes to tune synthetic truth;
claim neural criticality from behavioural data.
```

## Candidate Known-Truth Families

The first M2.8 generator should create competing causal organisations
explicitly.

At minimum:

```text
MECH0 general capacity
K -> behaviour

MECH1 static continuous APC
K + C_signal + A_evidence + T_commit + PC_calibration -> behaviour

MECH2 vigilance-gated APC
K + V + APC + V x APC -> behaviour

MECH3 profile-causes-control
latent profile -> APC configuration -> behaviour

MECH4 continuous-APC-causes-apparent-PACE
APC region -> behaviour -> coarse PACE phenotype

MECH5 dynamic regime plus APC
K + V + APC + R_t -> behaviour

MECH6 adaptive-corridor dynamics
K + V + APC + regulated corridor updating -> behaviour

MECH7 lock/excess-update failure modes
MI-lock and entropy-excess alternatives to successful adaptive recovery
```

A literal cusp/bifurcation generator is not part of the first M2.8 primary set.
It may be registered later as a late competitor after simpler continuous,
autoregressive, generic state and adaptive-corridor models have had a fair
chance to win.

## Candidate Scoring Families

The scoring tournament should escalate conservatively:

```text
static general factor;
static continuous APC;
static continuous nonlinear APC/readiness;
autoregressive continuous dynamics;
generic HMM/HSMM;
adaptive-corridor dynamics;
corridor plus lock/excess-update failure modes;
literal cusp/bifurcation only as a later registered competitor.
```

Held-out predictive density remains primary. Participant-isolated splitting is
required whenever person-level effects are present.

## Identifiability Contrasts

The required known-truth contrasts are:

```text
K-only vs APC:
Can mechanistic control dimensions be distinguished from a stable general
performance factor?

APC vs vigilance-gated APC:
Can readiness be separated from control efficacy?

continuous APC vs profile-causes-control:
Can discrete profiles be distinguished from continuous control regions?

APC-causes-PACE vs PACE-causes-APC:
Does PACE add causal structure or only describe regions of continuous APC
space?

static APC vs dynamic regime:
Do temporary regimes add held-out predictive value beyond static continuous
structure?

generic dynamics vs adaptive corridor:
Is adaptive corridor structure distinguishable from ordinary AR or HMM/HSMM
dynamics?

adaptive corridor vs lock/excess-update failure:
Can recoverable adaptation be separated from overconstraint and high-entropy
nonconvergent updating?
```

Transfer outcomes remain external to latent-state estimation. In M2.8 they may

real app data, transfer outcomes must be prospectively frozen before inspection.

## Prospective Wrapper-Swap Variables

M2.8 should prepare, but not run, the later wrapper-swap test by defining
outcome variables:

```text
first-contact dip when moving A -> B;
recovery slope on B;
recovery latency on B;
recovered B asymptote;
return cost B -> A;
hysteresis / asymmetry A->B vs B->A;
performance on held-out wrapper C;
later transfer to wrapper D or factorial mix;
delayed survival after days/weeks.
```

The central later empirical prediction is:

> Recovery from a structural perturbation predicts performance under a new
> perturbation, above baseline performance and generic capacity.

That prediction must be frozen before real wrapper-transfer outcomes are
inspected.

## Encouraging Synthetic Evidence

M2.8 would encourage moving toward prospective wrapper-transfer testing if:

```text
APC dimensions are recoverable beyond K;
vigilance/readiness can be separated from APC where generated separately;
continuous APC can be distinguished from profile-causes-control;
PACE adds value only when the generator gives it independent structure;
dynamic models outperform static continuous models when dynamics are true;
adaptive-corridor models beat generic AR/HMM/HSMM only when corridor dynamics
are true;
held-out synthetic perturbation outcomes are predicted by pre-perturbation
mechanistic estimates beyond baseline ability.
```

## Damaging Synthetic Evidence

M2.8 should weaken or narrow the forward theory if:

```text
APC parameters cannot be recovered beyond K under realistic sample sizes;
vigilance and APC are not separable in known-truth conditions where they differ;
PACE/profile models cannot be distinguished from continuous APC regions;
dynamic regimes do not improve held-out prediction when generated;
adaptive-corridor dynamics are not distinguishable from simpler AR/HMM/HSMM
models;
held-out synthetic perturbation outcomes are explained by baseline ability
alone.
```

## Execution Discipline

M2.8 must follow the compute contract:

```text
1. generator unit tests;
2. deterministic smoke;
3. small pilot;
4. scientific review;
5. confirmatory design only after review.
```

Every run must record:

```text
generator version;
known-truth family;
seed hierarchy;
participant split;
model registry;
truth columns stripped before fitting;
runtime;
checkpoint/resume status;
fit failures;
selection/ambiguity results;
whether transfer criteria were held out from latent fitting.
```

No M2.8 pilot or confirmatory run is authorised by this draft alone.

The current `mechanistic_identifiability_v1` scaffold authorises only
pre-outcome validation of:

```text
variable registry consistency;
gate-to-family mapping;
participant-isolated split requirement;
truth-column stripping requirement;
deterministic gate x truth-family x replicate schedule;
independent structural, nuisance, observation, split and model seeds;
real transfer outcomes remaining uninspected;
literal cusp/bifurcation remaining a later registered competitor only.
```

## Downstream Empirical Roadmap

If M2.8 supports mechanistic identifiability, the next empirical programme is:

```text
dynamic-regime tournament;
freeze wrapper-swap predictions;
prospective Attention Coach horizontal-transfer test;
randomised mechanism/intervention test;
vertical layer-transfer experiment;
niche and delayed-transfer testing.
```

The first major empirical Trident-G test should be the prospective held-out
wrapper experiment, not another static profile tournament.
